# 配置与数据迁移

全局文件统一使用 `<agent-dir>/extensions-data/<完整包名>/`。`<agent-dir>` 来自 `PI_CODING_AGENT_DIR`，未设置时为 `~/.pi/agent`。项目级配置与 Pi 自身的设置、凭据、会话不在本次迁移范围内。

## 迁移步骤

先更新扩展代码并退出所有 Pi 会话，在仓库根目录执行：

```bash
node bin/migrate-data.mjs --dry-run
node bin/migrate-data.mjs --apply
```

自定义宿主目录也可显式指定：

```bash
node bin/migrate-data.mjs --agent-dir /absolute/path/to/agent --dry-run
```

迁移器预先检查配置有效性与目标冲突，不合并或覆盖已有任务和历史。执行中发生错误会尝试回滚本次移动，并报告无法自动恢复的路径。重复运行不会再次搬移已迁移的数据。

迁移旧数据库需要 macOS 或 Linux 的 `lsof` 确认没有占用；缺少该工具或无法确认时停止执行。确认迁移完成后，再用更新后的扩展启动 Pi。

## 目录用途

| 位置 | 内容 | 创建时机 |
| --- | --- | --- |
| `<扩展包名>/config.json` | 用户配置 | 有持久化设置时 |
| `<扩展包名>/state/` | 工作区任务、执行状态和历史 | 扩展确实需要跨会话保存时 |
| `.backups/` | 停用实现留下的原始文件 | 迁移旧归档时 |

不预建空目录，不创建没有使用场景的 `cache/`。自动压缩依托 Pi 原生会话，不再另外保存数据库与工具输出副本。

## 自动压缩的配置转换

旧版本按“扣除输出预留与安全预留后的有效预算”计算临界阈值；新版本的 `thresholdPercent` 直接表示模型总上下文窗口的百分比。

迁移时保留原来的实际触发点：

```text
thresholdPercent = critical × (1 − outputReserveRatio − safetyReserveRatio) × 100
```

例如，旧临界阈值为 `0.6`，输出预留为 `0.12`，安全预留为 `0.06`，迁移后为 `49.2`。新安装默认使用总窗口的 `60%`。旧自动管理开关或原生压缩开关关闭时，迁移后的自动压缩也关闭。

新配置只保留 `enabled` 与 `thresholdPercent`。旧的分层阈值、归档位置、过期清理和固定条目设置不再进入新运行时。已有新配置优先保留。

### 项目级覆盖

迁移器不修改项目文件。若项目还使用旧的 `.pi/context-qos.json` 控制压缩，请把生效配置按上述公式转换为 `.pi/auto-compact.json`：

```json
{
  "enabled": true,
  "thresholdPercent": 60
}
```

示例中的 `60` 是新口径；转换时应使用旧项目覆盖与旧全局配置合并后的实际值，包括继承的预留比例。全局配置迁移后，缺少完整旧预留信息时无法无损解释旧项目阈值，扩展会提示转换项目配置并暂停自动压缩，不会猜测比例。只包含已移除归档设置的旧项目配置不影响新运行时。

## 旧归档的保留

旧目录连同原配置、SQLite 文件和正文一起保留到 `.backups/`；原文不被删除，也不会继续更新。该备份只用于回退旧实现或人工取证，新版本不会读取它，也不再注册引用召回工具。

显式配置在其他磁盘或目录中的归档不自动搬移、清理。旧实现的目录和配置可能同时存在多份；遇到歧义或已存在的备份目标时，迁移器会停止，要求先明确保留哪一份。

确认不需要回退后，可以自行删除旧归档备份；它不影响新版本的自动压缩。Pi 自身的会话文件需要另行保留。
