# 终端交互约定

目标是在 Ghostty 等终端中提供清晰、紧凑、可独立使用的扩展体验。这里约定交互方式，各扩展在自己的包内实现，不增加必须安装的共享 UI 扩展。

## 入口和操作

- 无参数命令先展示当前对象或最近一次实际行为。配置、完整命令目录和诊断放在次级入口。
- 先选择对象，再显示当前适用的操作。已完成、被阻塞、运行中等状态不共用一份无差别动作列表。
- 使用原生键盘选择、确认与返回；取消不产生“已取消”消息，也不写入数据。
- 历史直接命令可保持兼容，用户无需记忆全部命令才能完成日常操作。

## 信息位置

- 对话记录解释发生过的事实，记录当时的数据；展开后能核对原因和结果，不读取未来的可变状态。
- 编辑器状态条只显示持续相关的信息，默认最多两行；任务结束后隐藏，允许用户切换详细或隐藏模式。
- Footer 只承载可选的简短摘要；关键说明和主要操作必须另有本扩展自己的入口。
- 自定义 Footer 默认使用环境、模型、状态三层紧凑视图；完整诊断按需展开，也能在运行时恢复 Pi 原生 Footer。
- 原始接口响应、命令全集和内部诊断不放入日常主视图。

## 显示和运行方式

- 使用终端主题、文字层级和留白；文字与符号共同表达状态，不要求特殊字体或鼠标支持。
- 根据实际终端宽度换行或截断；按字符显示宽度处理中文、组合字符和 emoji，不能按字符串长度裁切。
- 用户和模型提供的文本进入终端前清除控制序列，再应用可信的主题样式。
- 通知区分一轮运行结束、取消和失败；策略注入不能描述成执行已验证，续跑请求不能描述成任务已完成。
- TUI、RPC 和文本输出模式分别处理；支持对话框不等于允许直接写入终端控制序列。

## 已落地的交互层级

- 策略、上下文整理和技能加载使用紧凑的对话活动记录；折叠态说明发生了什么，展开态保留当时的原因、来源和结果。
- 任务入口使用有高度边界的单列窗口，先展示当前工作集；已完成、已归档和全部任务作为同一窗口中的一级视图。
- 额度主视图只展示额度值、文字仪表、更新时间和当前错误；数据源、凭证和适配边界进入次级诊断。
- 通知主视图只展示开关、终端就绪状态和最近结果；协议、转发路径和环境说明进入次级诊断。
- 权限、任务、额度、通知和 Footer 的交互取消时静默返回，不产生无意义消息。

## 验收

单独加载一个扩展时，用户仍应能查看详情、完成主要操作并理解失败原因。组合行为的临时验证放在仓库之外；每个包的测试只验证本包及宿主公开契约。
