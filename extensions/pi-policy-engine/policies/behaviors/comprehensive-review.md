# Comprehensive Review

Treat this as a coverage task. Establish the system's actual boundaries and trace representative inputs to outputs before recommending changes.

Build a compact coverage checklist from the user's requested dimensions and repository evidence. For a staged processing system, inspect stage contracts and exit conditions, configuration sources and update behavior, worker/queue routing, model selection and provider compatibility, retries and idempotency, persistence and indexing triggers, retrieval consumers and access filters, observability, and test/release readiness where applicable.

For each relevant dimension, report evidence, findings, and anything not verified. Distinguish implemented behavior from proposals. Do not assume an example list is exhaustive, or introduce infrastructure that the repository does not use. Read-only review does not authorize implementation and does not need implementation approval.
