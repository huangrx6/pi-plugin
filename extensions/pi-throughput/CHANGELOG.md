# Changelog

## 0.7.0 - 2026-10-20

- 会话统计的输出速度改为 **Σtoken ÷ Σ时长**（`decodeTokens / decodeMs` 口径），不再是「每次调用 TPS 取平均」：同一份真实会话（81 次调用）上两种算法相差 25%（197 vs 248 t/s），长短调用混在一起时按调用次数平均会系统性偏高。p50 / p95 仍按单次调用分布给出，口径写进汇总文案。
- 会话统计新增「模型用时」（Σ 请求发出 → 消息结束）与「首 token 平均」两行，与宿主会话统计面板的四个字段对齐，便于逐项对账。
- 流中 token 估算从「一律 4 字符 1 token」改为按字符类型：CJK 1 字 1 token，其余 3.5 字符 1 token。旧比例对中文与工具参数系统性低估（16188 条真实 assistant 消息里字符 ÷ token 中位数 2.88、均值 2.73，按 4 估算的 token 数中位误差约 28%），导致流中 `rate` 偏低、结束时突然跳高。

## 0.6.0 - 2026-10-16

- 标签改为英文缩写：`rate: 42.1 t/s ttft: 3.2s`（等首 token 时 `ttft: waiting 3.2s`，空闲 `rate: -- ttft: --`），与底栏其余单元格的全英文标签同构。

## 0.5.0 - 2026-10-16

- 标签分隔符由全角 `：` 改为半角冒号加空格（`速率: 42.1 t/s 首字: 3.2s`）：全角冒号在等宽终端里占两列并留下空档，密集单元格显得松散。
- 空闲时不再清空状态格：显示 `速率: -- 首字: --`，会话开始或清空后该格仍然就位。

## 0.4.0 - 2026-10-16

- 状态文本改为与底栏其他单元格一致的 `描述：值` 排列：`速率：42.1 t/s 首字：3.2s`（等待期 `首字：等待 3.2s`），描述为两字中文，元素之间单空格。
- 首 token 延迟的文案由 `首 token 412ms` 简化为 `首字：412ms`。

## 0.3.0 - 2026-10-16

- 等待首 token 期间改为实时等待计时（`等待 3.2s`）并持续刷新，取代盲文 spinner：帧看起来像第二个 spinner，数字变化才是这一刻要传达的信息。
- 时长超过 60s 自动换单位（`1m35s`、`1h5m`），不再一直堆秒数；1–10s 保留一位小数，10–60s 取整秒。
- 同一轮里速率窗口未满时保留上一帧，不再把状态格闪空。

## 0.2.0 - 2026-10-16

- 状态文本改为不带装饰字形的纯文本：`42.1 t/s · 首 token 412ms`。原先的 ⚡ / ⏱ 前缀会被按字形清洗的底栏渲染器只吃掉前导字符，造成同一格内混排。
- 只渲染已经测到的指标：首 token 未到时不再输出 `… t/s` 占位，速率窗口未满时先只显示首 token 延迟。
- 等待首 token 与速率窗口未满期间改为盲文动画占位（`⠋ 等待首 token…`、`⠋ 测速中…`），80ms 帧间隔与宿主 spinner 一致；仅交互模式跑计时器并 `unref()`，首个增量、应答结束、会话关闭都会停表。

## 0.1.0 - 2026-10-16

- 在 Pi 状态集合发布实时输出速率与首 token 延迟（单一纯文本 key `pi-throughput`），流中按 `throttleMs` 节流刷新，结束后保留终值。
- 以 `before_provider_request` 为请求锚点、首个内容增量为 TTFT 终点；工具循环中的每次模型请求都重新锚定。
- 提供 `stream`（首 token 之后）与 `e2e`（含等待）两种速率口径，以及 `full` / `tps` / `ttft` 三种显示选择。
- 低于 `minWindowMs` 的流中速率只显示占位符，避免成批 flush 时的量化噪声；终值不受窗口限制。
- 每次模型调用写一条会话样本（模型、token、TTFT、时长、中断标记），不进入 LLM context，供 `/throughput stats` 按模型汇总平均值与 p95。
- 提供 `/throughput` 设置面板与子命令，配置持久化到 `<agent-dir>/extensions-data/pi-throughput/config.json`；非法值与坏文件退回默认值。
- provider 未上报 usage 时以字符数 ÷ 4 估算，`message_end` 的精确值一到即覆盖；token 数按显示宽度截断，状态文本先清洗控制字符。
