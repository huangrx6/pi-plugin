默认用分类表格显示路径、模型、额度、窗口、用量、集成和状态。一类信息一行，左侧分类、右侧集中展示相关字段；保留横线和分类分隔线，不画左右外边框。文字统一为低亮度灰色，线条更淡，不加粗或突出模型名。

## 快速开始

在本扩展包目录中执行，单独安装此扩展：

```bash
pi install "$PWD"
```

重启 Pi 或执行 `/reload`，默认启用完整视图。输入 `/footer` 选择显示方式。

## 三种视图

| 命令 | 显示内容 |
| --- | --- |
| `/footer full` | 按类别分行的完整表格，包含所有信息；默认模式 |
| `/footer compact` | 路径、模型、状态三个信息组 |
| `/footer native` | 停用本渲染器，恢复 Pi 原生底栏 |
| `/footer` | 打开原生选择器；取消不改变当前模式 |

**紧凑视图**保留工作目录、Git 分支、会话名、模型与思考等级、套餐状态、上下文占用和配置状态。它隐藏累计 Token、缓存、费用和集成状态。

**完整视图**将路径与分支集中在路径行，模型、平台与思考等级集中在模型行，输入、输出、缓存与费用集中在用量行。发布的状态按类别合入对应行。「输入 / 输出」表示累计 Token，「缓存读 / 缓存写」标明缓存 Token，「命中」表示最近一条助手消息的缓存命中率，`$` 表示已记录的费用。

下面是示意数据，实际颜色跟随 Pi 主题：

```text
──────┬─────────────────────────────────────────────────────────────────────────
 路径 │ ~/workspace/project   分支 main
──────┼─────────────────────────────────────────────────────────────────────────
 模型 │ glm-5.3   平台 zai-coding-cn   思考 high
──────┼─────────────────────────────────────────────────────────────────────────
 额度 │ GLM 5h: 44% (2h17m)  周: 84% (37h31m)
──────┼─────────────────────────────────────────────────────────────────────────
 窗口 │ 33.9% / 1.0M
──────┼─────────────────────────────────────────────────────────────────────────
 用量 │ 输入 4.7M   输出 149k   缓存读 61M   命中 99.9%   $23.062
──────┼─────────────────────────────────────────────────────────────────────────
 集成 │ MCP: 4 servers enabled   LSP Inactive
──────┼─────────────────────────────────────────────────────────────────────────
 状态 │ 权限 full   policy:auto
──────┴─────────────────────────────────────────────────────────────────────────
```

分类顺序固定，空类别不显示。表格始终只有分类与内容两列，所有行的分类分隔线对齐。右侧用三个空格隔开字段；窄屏优先让短字段完整换行，长路径和多行状态在当前类别内折行，续行分类栏留空。终端不足 10 列时退化为无框文字；容不下的宽字素显示省略号。

上下文占用未知时显示 `?`，而不是零。完整表格的标签、数值和状态文字统一使用主题的 `muted` 灰色，边框使用 `dim`；错误、暂停等文字仍然保留。紧凑视图保留三组折行排版与上下文阈值颜色。

## 状态如何归类

从 Pi 的公开状态集合读取文本，按状态 key 归类。同组按 key 排序；未知 key 进入状态组。

| Key 前缀 | 紧凑视图 | 完整视图 |
| --- | --- | --- |
| `quota:` | 模型组 | 额度组 |
| `context:` | 状态组 | 窗口组 |
| `config:` | 状态组 | 状态组 |
| `integration:` | 隐藏 | 集成组 |
| `usage:` | 隐藏 | 用量组 |
| 其他 | 状态组 | 状态组 |

无上述前缀时使用兼容规则：精确 key `quota` 归模型，精确 `mcp` 或包含 `lsp` 归集成，精确 `mode` 或包含 `policy` 归状态，包含 `context` / `qos` 归上下文。其余进入状态。

完整视图同时展示会话累计用量和自定义 `usage:` 状态。移除状态行首的装饰性闪电、插头、齿轮与圆环，不改写数值、错误或警告。只有整条状态是 `Context N%` 或 `上下文 N%`，且与宿主占用四舍五入一致时才省略重复摘要；附带暂停、失败等文字的状态始终保留。

## 显示与边界

- 先清理上游文本的终端控制序列，再统一使用 Pi 主题着色；有意保留的换行按多行单元格显示。
- 完整表格以字素为单位测量与换行，兼顾中文、组合字符和 emoji；实际字宽仍取决于终端与字体。
- 用量从会话记录汇总，在轮次结束后刷新；Git 分支变化触发重绘。
- 视图选择保存在当前扩展进程中，不写配置文件；重新加载后回到完整模式。
- Pi 的自定义底栏采用替换语义，同时启用多个渲染器时可能互相覆盖。
- 原生底栏的部分内部标记无法通过公开接口读取；需要完整原生信息时执行 `/footer native`。

## 开发

在本包目录运行：

```bash
npm ci
npm run check
npm test
```

`index.ts` 负责状态收集、视图切换与事件接线；`grid.ts` 负责完整表格的列宽、格内换行、边框和统一颜色；`layout.ts` 提供文本净化、显示宽度及紧凑布局。测试覆盖各宽度的边框对齐、长内容保留、颜色和三种视图的交互。
