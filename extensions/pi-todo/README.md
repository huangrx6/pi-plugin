<h1 align="center">pi-todo</h1>

<p align="center">把多步工作整理成可操作、可恢复的会话任务清单。</p>

<p align="center">
  <img alt="Node.js 22.19+" src="https://img.shields.io/badge/node-%E2%89%A522.19-555?style=flat-square" />
  <img alt="MIT License" src="https://img.shields.io/badge/license-MIT-555?style=flat-square" />
</p>

模型通过 `todo` 工具维护任务，你通过 `/todos` 查看和操作。清单按会话持久保存，同一会话内重新加载扩展或压缩对话后仍可继续使用；不同会话各自独立，互不可见。

## 快速开始

在本扩展包目录中执行，单独安装此扩展：

```bash
pi install "$PWD"
```

重启 Pi 或执行 `/reload`，然后告诉模型：

```text
把这次工作拆成任务，按顺序执行，每完成一项就更新状态。
```

输入 `/todos` 打开任务窗口。按 `n` 可以直接创建第一项。

## 实际体验

**先看到任务。** `/todos` 打开居中的单列任务窗口，按进行中、可开始、被阻塞的顺序列出当前工作。弹层使用固定最大宽度和四周留白，大终端下不会铺满屏幕；弱边框、主题表面色和独立的选中行底色把窗口与后方终端分开。选中任务后按 Enter 进入详情，只展示当前状态适用的操作。

| 任务状态 | 可执行的操作 |
| --- | --- |
| 进行中 | 标记完成、结束任务、让模型判断、查看详情、修改名称 |
| 可开始 | 开始任务、结束任务、让模型判断、查看详情、修改名称 |
| 被阻塞 | 结束任务、让模型判断、查看说明与依赖、修改名称 |
| 已完成 | 重新打开、归档、查看详情 |
| 已结束 | 重新打开、查看详情、修改名称 |
| 已归档 | 恢复到列表、查看详情 |

**三个日常视图。** 按 Tab 在「当前 / 历史 / 归档」之间切换。「历史」同时收纳已完成和主动结束的任务，并保留两者不同的图标、详情与后续操作；「归档」只是从历史中移走的冷记录。完整任务集合仍可通过 `/todos all` 直接打开，但不占日常导航。`/todos ready` 和 `/todos blocked` 可以直接打开相应筛选。按 `/` 搜索名称或 `#编号`，方向键逐项移动，PageUp / PageDown 翻页，Home / End 跳到首尾。列表高度根据终端自动限制，选中项始终留在可视区域。

**结果不占对话。** 详情、创建、修改和状态操作都留在同一个任务窗口，返回后保留视图、搜索词和选择位置。操作成功或失败显示在窗口底部，不向对话区追加长列表。任务窗口打开时会暂时隐藏编辑器上方的任务状态条，关闭后恢复原来的显示模式。

**创建立即可见。** 模型批量生成任务后会显示一份有界中文回执，直接列出前六项名称与编号；更多项目显示剩余数量并指向 `/todos`。这份回执只占少量终端高度，不需要先打开任务窗口才能知道刚刚生成了什么。

**进度轻量展示。** 编辑器上方默认显示一行横向任务表，集中呈现当前任务和完成进度；上下分隔线界定区域，间距交给 Pi 统一处理。窄终端下内容最多折成两行，没有活跃任务时隐藏。显示使用当前终端主题，中文、组合字符与 emoji 按显示宽度处理，任务文本中的终端控制序列会先被清理。

状态条可以隐藏，所有主要操作仍可从 `/todos` 完成。

## 日常命令

任务列表覆盖日常操作；直接命令适合已经知道任务编号的情况。

| 命令 | 用途 |
| --- | --- |
| `/todos` | 打开任务窗口，浏览、新增或选择任务操作 |
| `/todos 12` | 在任务窗口中打开 #12 的说明、阻塞原因和后续任务 |
| `/todos next` | 查看全部可开始任务 |
| `/todos here` | 恢复工作视角：当前任务与完成后会解锁的工作 |
| `/todos start 12` | 开始 #12；完成使用 `finish`，重开使用 `reopen` |
| `/todos close 12` | 结束一个尚未完成的任务；可在详情中重新打开 |
| `/todos history` | 查看已完成和主动结束的任务 |
| `/todos cleanup` | 删除其他会话中已经全部结束的任务文件，保留当前会话和未完成工作 |
| `/todos display compact` | 紧凑状态条；也支持 `full` 和 `hidden`，仅本次会话生效 |

<details>
<summary>分组查询与批量整理</summary>

| 命令 | 用途 |
| --- | --- |
| `/todos ready` | 在任务窗口中只看可开始任务 |
| `/todos blocked` | 在任务窗口中只看被依赖阻塞的任务 |
| `/todos completed` | 在任务窗口中查看已完成、未归档任务 |
| `/todos archived` | 在任务窗口中查看已归档任务 |
| `/todos all` | 在任务窗口中查看全部任务，包含归档记录 |
| `/todos archive 12 13` | 批量归档已完成任务 |
| `/todos archive completed` | 归档全部已完成任务 |
| `/todos restore 12 13` | 恢复指定归档任务 |
| `/todos restore archived` | 恢复全部归档任务 |

归档只改变可见性，用来让长期历史保持清爽；任务不多时可以完全不使用。恢复已归档任务后，它仍保留原来的生命周期状态；若要再次执行，再选择「重新打开」。结束任务只表示不再继续，不代表验收条件已经满足。

## 模型与任务规则

模型侧 `todo` 工具支持创建、查询、编辑、状态流转、依赖关系、归档和恢复，也提供删除与清空操作。开始任务使用 `start`，完成任务优先使用更自然的 `complete`（`finish` 等价）；已经处于目标状态时重复调用会返回“无变化”，不写盘也不增加修订号。扩展要求模型在多步工作中维护任务，并在最终答复前核对真实进度。完成任一任务后，工具结果会同时列出仍未结束的任务，促使模型及时检查遗漏；插件不会仅凭编号顺序自动把任务标记完成。

任务从待办进入进行中，再进入已完成；进行中任务也可以被明确结束，已完成或已结束任务可以重开。依赖未满足时，待办任务显示为被阻塞。完成任务或重新打开任务后，结果会说明新就绪或重新受阻的下游工作。

同一会话重新打开时，如果仍有进行中的任务，可以直接在任务详情中继续任务、让当前模型只做判断、标记完成，或结束任务。模型判断只返回建议，不会直接修改任务状态；信息不足时应返回无法判断。不同会话的清单互相隔离，新会话从空清单开始。

| 规则 | 实际含义 |
| --- | --- |
| 批量变更原子提交 | 任一目标不满足条件，整次变更都不提交 |
| 依赖校验 | 拒绝缺失、已删除、自身及循环依赖 |
| 编号持续递增 | 清空列表后也不复用旧编号，避免旧引用指向新任务 |
| 删除为终态 | 删除的任务保留墓碑，不能再编辑或恢复；归档可恢复 |
| 冲突明确返回 | 并发提交冲突返回 `cas-conflict`，不以自动重试覆盖其他写入 |

## 批量创建：createMany

一次工具调用里需要创建多个任务时，使用 `createMany` action 代替连续 `create`。一次提交、一次原子写入，省去 N 次 CAS 风险与轮次。

```json
{
  "action": "createMany",
  "items": [
    { "subject": "梳理现有测试", "activeForm": "梳理现有测试" },
    { "subject": "补齐核心场景", "blockedBy": [1000] },
    { "subject": "接通 CI" }
  ]
}
```

- `items` 接受 1–50 条；每条携带 `subject` 与可选 `description` / `activeForm` / `blockedBy`。
- **原子回滚**：任一条因 subject 为空、blockedBy 缺失、循环依赖等原因被拒，**整批不写**；返回的错误以第一条失败为准。
- **blockedBy 范围**：只解析“初始 state 中已存在的任务” + “本批前序已成功 items”。**不支持**本批后向引用（`items[k].blockedBy` 不能引用 `items[k+1..]`）；如需新任务互相依赖，分两次 `create` 调用（PR1 的 CAS 重试会自动处理）。
- **id 分配**：按 `initial.nextId, +1, +2, ...` 顺序，确保前向引用可解析。
- **与 `create` 的关系**：模型在 3+ 任务同属一个计划时优先选 `createMany`；逐条生命周期操作使用 `start` / `complete` / `reopen`，字段编辑使用 `update`。
- **持久化冲突**走与单条相同的 `cas-conflict` 返回，并自动走 3 次线性 backoff 重试（15ms / 30ms），重试耗尽后才向模型报告。

## 存储与边界

默认数据保存在 `~/.pi/agent/extensions-data/pi-todo/state/` 下的 JSON 文件中；如果宿主设置了 `PI_CODING_AGENT_DIR`，则跟随对应目录。每次提交保存版本号、任务状态和下一个编号。

启动时只会清理同时满足三个条件的其他会话文件：会话任务已存在超过 30 天、文件最近 7 天没有更新，并且已经没有待办或进行中任务。当前会话、最近使用的会话、较新的会话、仍包含未完成任务的会话以及无法安全解析的文件始终保留。需要立即整理时使用 `/todos cleanup`；手动清理不等待时间门槛，但同样不会删除当前会话或未结束工作。

运行时只使用上面的 canonical state 目录。旧版 agent 根目录下的 `pi-todo/` 不会被自动读取或合并；需要保留旧任务时请先在扩展之外完成一次离线迁移。任务数据需要保留，本扩展没有需要单独落盘的配置或缓存。

清单身份来自当前会话 id：每个会话一份独立清单，同一目录下并发打开的多个会话互不干扰；同一会话在不同目录恢复时仍能看到自己的清单。扩展不会向上寻找 Git 根目录来合并任务，也不使用对话分支恢复旧状态。

`/todos` 面向交互模式；模型工具仍是独立的任务操作接口。任务窗口最大宽度为 104 列，高度最多占终端的 82%，窄终端会自动收缩，内部维护独立的可视窗口和滚动位置。背景使用 Pi 主题中的中性深层表面色，因此会跟随深色、浅色或自定义主题；终端字符层不支持单个弹层的透明模糊。`activeForm` 用于模型提示，任务说明在详情中展示。

本包注册工具名 `todo`。若其他已安装代码也注册同名工具，需要解决名称冲突后使用。

## 开发与文档

在本包目录运行：

```bash
npm ci
npm run check
npm test
```

包声明 Node.js 22.19 或更高版本，与当前 Pi SDK 的运行要求一致。`index.ts` 连接工具、命令和生命周期；状态机、依赖查询、持久存储和终端显示分别可测。运行时使用 Pi SDK 的代理目录 API。

测试覆盖任务流转、依赖、持久化冲突、窗口内操作、百项列表滚动与终端渲染，临时文件创建在系统临时目录。
