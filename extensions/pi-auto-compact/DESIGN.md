# Pi Auto Compact · 实现设计

扩展只决定何时请求 Pi 原生压缩，以及何时允许被中断任务继续。Pi 会话仍是对话与压缩记录的唯一持久化来源。

## 请求路径

```text
context hook
    │
    ├─ 用量未知 / 暂停 / 低于阈值 → 原请求继续
    │
    └─ Pi tokens / contextWindow ≥ thresholdPercent / 100
          │
          └─ ctx.compact()
               ├─ 失败 / 取消 → 记录结果，停止本次尝试
               ├─ 新输入 / 会话、分支、模型变化 → 回调失效
               └─ 成功且 idle、无排队输入 → 发送一次隐藏继续消息
```

`context` hook 不返回替换消息，也不修改传入内容。扩展不注册工具、不监听工具结果、不生成归档引用。

## 文件职责

| 文件 | 职责 |
| --- | --- |
| `index.ts` | 生命周期、阈值判断、命令面板与 Pi 活动呈现 |
| `config.ts` | 只读配置、受信任项目覆盖、旧阈值换算 |
| `continuation.ts` | 压缩请求去重、过期回调隔离与一次性续跑 |
| `terminal.ts` | 终端控制字符清理、显示宽度与换行 |

## 用量与配置

判断依据是 `getContextUsage()` 返回的 `tokens` 和 `contextWindow`。任一值未知或无效就不触发，不使用文本长度猜测完整上下文，也不引入额外预算预留。百分比可能超过 100%，如实显示。

默认 `enabled: true`、`thresholdPercent: 60`。全局新配置优先于同级旧配置，受信任项目配置最后覆盖。旧配置的有效预算阈值换算为总窗口百分比；归档字段不参与新版行为。全局已迁移但项目仍含旧自动压缩设置时，拒绝推测丢失的全局预留比例，提示先转换项目配置并暂停自动压缩。配置解析失败会暂停自动压缩并提示修正，不静默退回可能与用户意愿相反的启用状态。

所有运行期设置仅保存在内存。无配置文件时不创建目录。

## 续跑约束

每次请求持有 generation、session id 和唯一 pending token。用户输入、切换会话、分支或模型、关闭会话使过期回调失效。仅当压缩成功、当前 agent 空闲且没有待处理消息时发送续跑。

续跑消息保存当前目标及与基础系统提示不同的执行约束。基础提示未知时保留完整有效提示，避免丢失限制。消息使用 `display: false`，活动结果通过单独的 custom entry 呈现。

attempted 标记阻止失败或压缩未降低用量时的重复请求；用量降到阈值以下后重置。新用户输入可开始新的尝试，自动续跑不会重置该标记。设置命令在已有压缩请求进行时保留其回调，避免操作面板导致任务停在中途。

## 存储与迁移

新版无自建数据库、正文目录或垃圾清理任务。`pi.appendEntry` 写入的是 Pi 自己管理的会话活动。旧归档不自动删除，新版不会打开它，也不支持解析旧 `ctx://` 引用；历史内容恢复需要保留旧版本及其数据。

## 验证

本地 shim 与安装的 Pi SDK 分别执行类型检查。离线 SDK 测试实际启动会话、触发压缩、模拟取消与新输入接管，并验证执行约束进入续跑上下文。单元回归覆盖未知用量、精确阈值、无效配置、旧配置转换、过期回调、无效压缩不循环、压缩中调整设置，以及中文和 emoji 的终端换行。
